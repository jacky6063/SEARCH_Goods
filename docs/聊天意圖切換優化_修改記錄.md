## 🐛 問題描述

### 問題現象

當用戶進行多輪對話後，系統無法正確識別並切換到「住宅維修」意圖。

**測試場景：**
```
用戶：你們公司做什麼的？          → ✅ 正確識別為「公司資訊」
系統：[回覆公司簡介]
用戶：有賣什麼商品？              → ✅ 正確切換到「商品搜尋」
系統：[顯示商品列表]
用戶：我家冷氣壞了需要維修        → ❌ 無法切換到「住宅維修」
```

### 預期行為

無論對話歷史如何，當用戶輸入包含維修相關關鍵字的訊息時，系統應立即切換到「住宅維修」意圖。

### 實際行為

系統繼續停留在「商品搜尋」或「公司資訊」模式，無法切換到「住宅維修」。

---

## 🔍 根本原因分析

### 問題根源

透過代碼審查發現三個關鍵問題：

#### 1. **系統鎖定機制過於嚴格**

**位置：** `frontend/index.html` - `detectIntent()` 函式 (約1683行)

```javascript
// ❌ 原有邏輯（問題代碼）
function detectIntent(message) {
    if (systemLocked && intentModeLock === 'system') {
        // 直接返回當前意圖，不重新檢測
        return currentIntentMode;
    }
    // ... 後續檢測邏輯
}
```

**問題：** 當 `systemLocked` 為 `true` 時，函式直接返回 `currentIntentMode`，完全不進行關鍵字檢測，導致意圖無法切換。

#### 2. **歷史訊息檢測使用錯誤函式**

**位置：** `frontend/index.html` - `routeMessageByIntent()` 函式 (約1760行)

```javascript
// ❌ 原有邏輯（問題代碼）
for (let i = 0; i < chatHistory.length; i++) {
    const historyIntent = detectIntent(chatHistory[i].content);
    // ...
}
```

**問題：** 使用 `detectIntent()` 檢測歷史訊息時，會受到當前鎖定狀態影響，導致歷史意圖檢測不準確。

#### 3. **意圖切換門檻過高**

**問題：** 原系統要求至少 2 個關鍵字才能切換意圖，但許多有效的維修查詢只包含 1 個關鍵字（如「冷氣維修」）。

## 💡 修改方案

### 解決策略

採用「三管齊下」的修復策略：

1. **新增純淨檢測函式** - 建立不受狀態影響的意圖檢測
2. **優化意圖切換邏輯** - 支援強意圖切換，降低切換門檻
3. **修正歷史檢測方法** - 使用純淨函式檢測歷史訊息

### 架構設計

```
┌─────────────────────────────────────────┐
│         意圖檢測系統架構                │
├─────────────────────────────────────────┤
│                                          │
│  detectIntentPure(message)              │
│  ├─ 純關鍵字匹配                        │
│  ├─ 不受鎖定狀態影響                    │
│  └─ 用於歷史訊息分析                    │
│                                          │
│  detectIntent(message)                  │
│  ├─ 檢查手動鎖定（優先級最高）          │
│  ├─ 檢查強意圖切換（≥1個關鍵字）        │
│  ├─ 檢查系統鎖定（可被強意圖覆蓋）      │
│  └─ 預設行為（維持當前意圖）            │
│                                          │
│  routeMessageByIntent(userMessage)      │
│  ├─ 使用 detectIntentPure 檢測歷史      │
│  ├─ 使用 detectIntent 檢測當前訊息      │
│  └─ 根據意圖路由到對應 API              │
│                                          │
└─────────────────────────────────────────┘
```

## 📝 程式碼變更詳細說明

### 變更 1：新增 `detectIntentPure()` 函式

**檔案：** `frontend/index.html`  
**位置：** 約 1635-1673 行

```javascript
/**
 * 純粹的意圖檢測函式（不受鎖定狀態影響）
 * 用於歷史訊息分析，確保檢測結果不受當前系統狀態污染
 * 
 * @param {string} message - 要檢測的訊息內容
 * @returns {string} 'repair' | 'shopping'
 */
function detectIntentPure(message) {
    if (!message || typeof message !== 'string') {
        return 'shopping';
    }

    const lowerMsg = message.toLowerCase();
    
    // 計算維修關鍵字匹配數
    let repairScore = 0;
    for (const keyword of REPAIR_KEYWORDS) {
        if (lowerMsg.includes(keyword.toLowerCase())) {
            repairScore++;
        }
    }
    
    // 計算購物關鍵字匹配數
    let shoppingScore = 0;
    for (const keyword of SHOPPING_KEYWORDS) {
        if (lowerMsg.includes(keyword.toLowerCase())) {
            shoppingScore++;
        }
    }
    
    console.log(`[detectIntentPure] 訊息: "${message.substring(0, 30)}..." | 維修分數: ${repairScore} | 購物分數: ${shoppingScore}`);
    
    // 純粹根據關鍵字分數決定意圖
    if (repairScore > shoppingScore) {
        return 'repair';
    } else {
        return 'shopping';
    }
}
```

**變更理由：**
- 提供不受鎖定狀態影響的純淨檢測邏輯
- 專門用於歷史訊息分析，避免狀態污染
- 簡化邏輯，只根據關鍵字分數決定意圖

### 變更 2：修改 `detectIntent()` 函式

**檔案：** `frontend/index.html`  
**位置：** 約 1683-1751 行

**主要變更點：**

#### 2.1 移除過度嚴格的系統鎖定檢查

```javascript
// ❌ 刪除的代碼
if (systemLocked && intentModeLock === 'system') {
    return currentIntentMode;
}

// ✅ 改為支援強意圖切換
if (systemLocked && intentModeLock === 'system') {
    // 檢測是否有強烈的相反意圖
    const oppositeIntent = currentIntentMode === 'repair' ? 'shopping' : 'repair';
    const oppositeKeywords = oppositeIntent === 'repair' ? REPAIR_KEYWORDS : SHOPPING_KEYWORDS;
    
    let oppositeScore = 0;
    for (const keyword of oppositeKeywords) {
        if (lowerMsg.includes(keyword.toLowerCase())) {
            oppositeScore++;
        }
    }
    
    // 如果檢測到至少 1 個相反意圖的關鍵字，允許切換
    if (oppositeScore >= 1) {
        console.log(`🔄 強意圖切換: ${currentIntentMode} → ${oppositeIntent} (關鍵字數: ${oppositeScore})`);
        systemLocked = false;
        intentModeLock = null;
        currentIntentMode = oppositeIntent;
        return oppositeIntent;
    }
    
    // 否則維持系統鎖定
    console.log(`🔒 維持系統鎖定: ${currentIntentMode}`);
    return currentIntentMode;
}
```

**變更理由：**
- 原邏輯完全阻止意圖切換，不符合實際需求
- 新邏輯允許「強意圖切換」：當檢測到相反意圖關鍵字時，自動解除鎖定
- 降低切換門檻從 2 個關鍵字到 1 個關鍵字，提升響應性

#### 2.2 新增詳細的 Console 日誌

```javascript
console.log(`[detectIntent] 訊息: "${message.substring(0, 50)}..."`);
console.log(`  維修分數: ${repairScore} | 購物分數: ${shoppingScore}`);
console.log(`  當前意圖: ${currentIntentMode} | 鎖定狀態: ${systemLocked ? '是' : '否'} (${intentModeLock || 'N/A'})`);
console.log(`  檢測結果: ${detectedIntent}`);
```

**變更理由：**
- 方便開發者追蹤意圖檢測過程
- 有助於快速診斷問題

### 變更 3：修正 `routeMessageByIntent()` 函式

**檔案：** `frontend/index.html`  
**位置：** 約 1760-1782 行

```javascript
// ❌ 原有代碼
for (let i = 0; i < chatHistory.length; i++) {
    const historyIntent = detectIntent(chatHistory[i].content);
    // ...
}

// ✅ 修正後的代碼
for (let i = 0; i < chatHistory.length; i++) {
    const historyIntent = detectIntentPure(chatHistory[i].content);
    // ...
}
```

**變更理由：**
- 使用 `detectIntentPure()` 確保歷史意圖檢測不受當前鎖定狀態影響
- 保證歷史訊息分析的準確性
