# 搜尋判斷式說明

本文件紀錄聊天查詢的篩選與守門邏輯，協助快速確認「哪些查詢會被視為可販售商品」以及「何時回覆 OOS（超出販售範圍）」。

## 1. 分類白名單來源
- 後端以 `data/goods_categories.csv` 為唯一權威資料。`backend/services/categories_service.py` 會載入啟用的 L1/L2/L3，並解析 `Synonyms` 欄位。
- 函式 `get_category_terms()` 會輸出經正規化（去空白、lowercase）的字詞集合，供 LLM 判斷查詢是否出現在白名單內。

## 2. 查詢偵測流程
1. `chat_reply()` 取得使用者輸入後，先執行既有的關鍵字守門（3C、家電等）。
2. 若未被上述條件擋下，`_prepare_chat_context()` 會：
   - 解析關鍵字 `_extract_keywords()`；
   - 以 `_search_products_for_chat()` 搜尋 CSV；
   - 判定 `_should_flag_oos()`：僅當查詢既沒有白名單詞彙、也沒有分類上下文（例如 LLM 層級或結構化篩選），才回傳 `oos_suspected=True`。
3. `chat_reply()` 在建立 LLM 回覆前檢查 `oos_suspected`，若為真則立即呼叫 `_build_oos_response()`，回覆「目前暫不販售該品類」並附帶 `meta.oos_reason=whitelist_miss`。

## 3. OOS 回覆模式
- **關鍵字守門**：`chat_reply()` 內的 `oos_keywords` 用於擋下 3C/家電等明確規則，`meta.oos_reason=keyword_block`。
- **白名單守門**：如上敘述，查詢字詞若完全不在 `goods_categories.csv` 的啟用分類或同義詞內，且沒有其它分類指標，就視為 OOS；一旦偵測到合法分類，上層會覆寫 `oos_suspected=False`。
- 兩種模式共用 `_build_oos_response()`，維持一致訊息與 `display_mode="text_only"`。

## 4. 食品篩選修正
- `_is_food_item()` 改用 `FieldAccessor` 讀取 L1/L2/L3，確保「非食品查詢」不會意外帶出食品商品。
- 若查詢字詞不是食品且搜尋結果都是食品，系統會自動過濾並回退至 OOS 或 fallback 引導。

## 5. 開發注意事項
- 若日後新增可販售類別，只需更新 `goods_categories.csv`（或其 Synonyms），白名單與守門會自動生效。
- 若需要疑難排解，可在 `chat_reply` 日誌中觀察 `meta.oos_reason` 與 `suspected_keywords`，快速確認是關鍵字守門或白名單守門觸發。
