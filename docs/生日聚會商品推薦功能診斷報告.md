# 生日聚會商品推薦功能問題診斷報告

## 📋 問題摘要

**用戶需求**: 辦一場生日聚會，需要餅乾類及飲料類商品，總預算 2000 元  
**預期功能**: 系統應智能推薦適合的餅乾和飲料組合，並控制在預算範圍內  
**實際情況**: 功能部分可用，但存在多個改進空間

## 🔍 功能測試結果

### ✅ 正常運作的部分

1. **聊天API響應正常**
   - API端點 `/api/chat` 可正常接收請求
   - 能理解自然語言查詢「生日聚會」、「餅乾類」、「飲料類」
   - 正確解析預算限制（2000元、1500元）

2. **商品搜尋基本功能**
   - 能找到相關商品（餅乾類找到6款，飲料類找到6款）
   - 能提供完整商品資訊（編號、名稱、價格、購物連結）
   - 支援價格過濾

### 🚨 發現的問題

#### 問題1: 商品類別識別不精確
```
用戶要求: 餅乾類 + 飲料類
實際返回: 
- 餅乾類: ✅ 五香胡椒餅、岩燒海苔餅等（符合）
- 飲料類: ❌ 甘麥大棗燉包、十全燉包等（中藥包，非飲料）
```

#### 問題2: 預算控制不完整
```
餅乾類商品總計: 80×4 + 95 + 90 = 505元
飲料類商品總計: 111×3 + 135 + 95 + 90 = 653元
總計: 1158元 < 2000元 ✅

但系統沒有：
- 主動計算總金額
- 建議最佳組合
- 提供預算剩餘提醒
```

#### 問題3: LLM功能受限
```
調試輸出顯示:
[DEBUG] OPENAI_API_KEY is placeholder value
[DEBUG] No OpenAI client available, using mock reply

問題: LLM功能被降級為模擬回應，影響智能推薦品質
```

## 🧩 根本原因分析

### 1. 商品分類系統問題

**問題根源**: 
- 系統將「燉包」類商品歸類為飲料，實際為食品調理包
- 商品分類邏輯過於寬鬆，缺乏精確的類別對應

**影響程度**: 中等 - 影響推薦準確性但不完全阻斷功能

### 2. 預算管理邏輯缺失

**問題根源**:
- 系統能識別預算上限但缺乏組合優化
- 沒有總價計算和預算建議功能
- 缺乏多商品購物清單管理

**影響程度**: 高 - 核心購物體驗功能缺失

### 3. LLM服務配置問題

**問題根源**:
```python
# 在 llm_service.py 中
OPENAI_API_KEY = os.getenv("OPENAI_API_KEY")  # 返回 placeholder 值
```

**影響程度**: 高 - 限制了智能對話和個性化推薦能力
