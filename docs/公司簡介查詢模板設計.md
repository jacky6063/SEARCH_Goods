# 公司簡介資料庫查詢模板 — 架構設計

## 1. 背景與目標
- **需求**：客戶在聊天介面詢問公司資訊（經營項目、組織成員、客服窗口等），系統需即時回覆。
- **既有系統**：FastAPI 後端 + LLM Chat Router，主要處理商品查詢。新功能須與既有聊天管線整合，不影響商品搜尋。
- **目標**：
  1. 建立可擴充的「公司簡介資料庫」並定義欄位格式。
  2. 規劃查詢流程：意圖偵測→資料庫匹配→生成回覆→快取。
  3. 提供模板給未來新增其他公司資料（多品牌、多站台）。

## 2. 架構概覽
```mermaid
flowchart LR
    User(使用者詢問<br/>公司資訊) --> FE[前端聊天介面]
    FE --> API[/api/chat]
    API --> ChatRouter[chat_router_goods_action]
    ChatRouter --> IntentLLM[LLM + 規則意圖偵測]
    IntentLLM -->|CompanyInfo| CompanySvc[Company Profile Service]
    CompanySvc --> ProfileStore[公司簡介資料庫<br/>(JSON/CSV + 快取)]
    CompanySvc --> ResponseBuilder[模板化回覆產生器]
    ResponseBuilder --> ChatRouter --> FE --> User
```

## 3. 模組設計
### 3.1 意圖判斷與路由
- **新增規則**：在 `llm_service._detect_conversation_intent` 或 Chat Router 中加入 `company_profile` 類型，觸發條件如「公司介紹、經營項目、客服電話、組織架構」。
- **LLM 支援**：若規則無法確定，可交由 LLM 進行 `company_info` 標記，並輸出 `structured_filters={"company": "...", "topic": "客服"}`。
- **路由策略**：
  1. 若偵測為公司資訊→呼叫 `company_profile_service.query(company, topic, locale)`。
  2. 若找不到資料→回覆友善訊息，並提供補充（如客服信箱）。

### 3.2 Company Profile Service（新模組）
- **職責**：
  - 載入公司資料（本地 JSON/CSV 或後端 DB）。
  - 依 `company_id` + `topic` 快速搜尋資料（內建索引）。
  - 提供多語內容（繁中/英文）。
  - 回傳結構化物件給 Response Builder。
- **介面草案**：
  ```python
  class CompanyProfileService:
      def load_from_file(path: Path) -> None
      def query(company: str, topics: List[str], locale: str = "zh-TW") -> Dict[str, Any]
      def get_contact_info(company: str) -> Dict[str, str]
  ```
- **快取策略**：啟動時載入 + 熱更新（類似 `catalog_service.snapshot`）；資料更新時可透過 Admin API 重新載入。

### 3.3 Response Builder（模板）
- **輸入**：`query_context`（使用者文字、歷史）、`profile_data`（結構化）、`topics`。
- **輸出**：標準 `ChatResponse`，包含：
  - `reply`：語句化回答（模板 + LLM 補強）。
  - `structured_payload`: `{summary, sections:[{title, content}]}`。
  - `action`: 若需要連結官方網站或客服，提供 `{"type":"external_link","url":...}`。
- **模板例示**：
  ```
  公司名稱：{company_name}
  經營項目：{business_scope}
  主要據點：{headquarters}
  客服：{service_hours} / {service_phone}
  如果需要 human agent，請輸入「客服」。
  ```

### 3.4 Admin / Data Ops
- 新增 `/api/admin/upload-company-profile`：上傳公司資料檔。
- 新增 `/api/admin/reload-company-profile`：手動觸發重新載入。
- 日誌：記錄查詢命中率、缺漏欄位，供後續擴充。

## 4. 資料庫檔案格式
### 4.1 推薦格式：JSON Lines（UTF-8）
- 優點：易於 append / diff；支援多語欄位。
```json
{
  "company_id": "ACME",
  "locale": "zh-TW",
  "company_name": "艾可米股份有限公司",
  "overview": "專注於智慧零售與客服系統。",
  "business_scope": [
    "智慧客服系統開發",
    "商品搜尋引擎整合",
    "企業顧問服務"
  ],
  "organization": {
    "founder": "張小艾",
    "ceo": "李凱",
    "teams": [
      {"name": "RD", "lead": "王工", "members": 24},
      {"name": "CS", "lead": "林客服", "members": 12}
    ]
  },
  "contacts": {
    "service_phone": "+886-2-1234-5678",
    "service_email": "support@acme.com",
    "service_hours": "週一至週五 09:00-18:00",
    "line_id": "@acmeservice"
  },
  "faq": [
    {"question": "客服時段？", "answer": "週一至週五 09:00-18:00。"},
    {"question": "主要服務？", "answer": "智慧零售與客服系統。"}
  ],
  "keywords": ["公司介紹", "客服電話", "組織", "經營項目"]
}
```

### 4.2 CSV 備選格式
| company_id | locale | field             | value                                    |
|-----------|--------|-------------------|------------------------------------------|
| ACME      | zh-TW  | company_name      | 艾可米股份有限公司                       |
| ACME      | zh-TW  | business_scope    | 智慧客服系統開發；商品搜尋引擎整合      |
| ACME      | zh-TW  | contacts.phone    | +886-2-1234-5678                         |
| ...       | ...    | ...               | ...                                      |

> CSV 需搭配 `field` 欄位拆解多層結構，較難維護；建議以 JSON 為主。

### 4.3 索引建議
- **Primary Key**：`company_id + locale`
- **輔助索引**：`keywords`（供簡易全文檢索）、`topics`（如客服、經營項目）。
- **欄位命名規範**：使用 `snake_case`，多語欄位以 `locale` 分開。

## 5. 整合流程
1. **資料準備**：依 JSON 模板建立 `company_profiles.jsonl`，放置於 `data/company_profiles/`。
2. **服務啟動**：`company_profile_service.load_from_file()` 讀取並建索引。
3. **意圖觸發**：使用者詢問 → Chat Router 判斷 → 呼叫服務。
4. **回覆組裝**：Response Builder 套模板，必要時呼叫 LLM 補強語句。
5. **快取與記錄**：將結果寫入 `bundle_service`，並記錄命中率供後續調整。

### 6.3 LLM 智能匹配邏輯

#### **關鍵字優先級匹配**
```python
# 1. 聯絡資訊 (最高優先級)
CONTACT_KEYWORDS = ["電話", "聯絡", "客服", "地址", "官網"]

# 2. 服務項目
SERVICE_KEYWORDS = ["服務", "做什麼", "業務", "提供", "項目"]

# 3. 公司介紹
COMPANY_KEYWORDS = ["公司", "介紹", "背景", "關於", "你們是"]

# 4. 營業時間
HOURS_KEYWORDS = ["營業時間", "幾點", "上班", "服務時間", "週末"]

# 5. 促銷活動
PROMO_KEYWORDS = ["優惠", "促銷", "活動", "折扣", "特價"]

# 6. FAQ 匹配 (使用向量相似度)
FAQ_MATCHING = semantic_search(query, faq_keywords)
```

#### **匹配流程**
```python
def match_company_info_topic(query: str) -> str:
    """判斷公司資料查詢的主題類型"""
    query_lower = query.lower()
    
    # 優先級匹配
    if any(kw in query_lower for kw in CONTACT_KEYWORDS):
        return "contact"
    elif any(kw in query_lower for kw in SERVICE_KEYWORDS):
        return "service"
    elif any(kw in query_lower for kw in COMPANY_KEYWORDS):
        return "overview"
    elif any(kw in query_lower for kw in HOURS_KEYWORDS):
        return "hours"
    elif any(kw in query_lower for kw in PROMO_KEYWORDS):
        return "promotion"
    else:
        # 降級到 FAQ 匹配
        return "faq"
```

## 7. 後續擴充建議
- **多公司/多品牌**：`company_id` 可對應不同客戶；於 Admin 端配置預設公司。
- **權限控管**：管理端點需 `ADMIN_TOKEN`；若資料包含敏感資訊，可考慮 RBAC 與加密儲存。
- **QA/測試**：新增 `backend/tests/test_company_profile.py`，驗證資料載入、意圖判斷、模板輸出。
- **前端支援**：在聊天介面提供快速按鈕（如「客服資訊」、「公司介紹」），並於顯示區塊支援 `structured_payload`。
- **語意搜尋增強**：整合向量搜尋 (embedding) 提升 FAQ 匹配準確度。
- **A/B 測試**：記錄不同回應模板的使用者滿意度，優化話術。
