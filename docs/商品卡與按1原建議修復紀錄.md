# 商品卡與「按 1 原建議」修復紀錄

## 1. 背景
- 後端 (`chat_router_goods_action.py`) 已改版為輸出 `structured_payload/structured_products`，但前端仍依賴舊欄位 (`items/suggestion_ids`) 取得商品資訊。
- 「按 1 原建議」按鈕需要在前端快取最新的建議結果，點擊後再呼叫 `/api/search` 重新顯示商品卡。
- 若快取為空，按鈕即無法作用並提示「當前快取狀態：無快取」。

## 2. 問題原因
1. `window.lastAssistantJson` 未在主要聊天流程中更新，導致監聽腳本取得不到 `structured_products`。
2. `original_suggestion_all.js` 只掃描舊欄位（`suggestion_ids` 等），未支援 `structured_products` / `structured_payload.items`。
3. 建議結果只快取在 slot `0`，但「1 原建議」按鈕會讀取 slot `1`，造成有資料卻被判定為無快取。

## 3. 修復內容
1. `frontend/index.html`
   - 在 `routeMessageByIntent` → `/api/chat` 回覆後新增 `window.lastAssistantJson = data;`，確保每次聊天回覆都寫入最新 JSON。
   - 在收到 `structured_items` 時同時呼叫 `setSuggestCache(1, …)` 與 `setSuggestCache(0, …)`，讓按鈕 `1` 能讀到快取。
2. `frontend/public/patches/original_suggestion_all.js`
   - 在 `collectAllIdsFromJson()` 補掃 `structured_products` 及 `structured_payload.items`，確保可從新版欄位取出商品 ID。

## 4. 測試方式
1. 重新載入前端頁面。
2. 輸入一般購物需求（例如「我要買廚房洗滌清潔用品」）。
3. 確認商品卡正常顯示。
4. 切換模式或回到聊天，再點「1 原建議」按鈕；控制台不再顯示「無快取」，並成功載入商品卡。

## 5. 後續建議
- 只要 API 回覆結構有變動，務必檢查：`structured_products` → `setSuggestCache(type, …)` → `window.lastAssistantJson` → 按鈕事件巡迴，確保資料流完整。
- 若新增其他建議按鈕（例如 2=特價關聯、3=智慧搭配），也要確認快取 slot 與 `setSuggestCache` 呼叫對應。

## 6. 商品卡資料來源
- 後端 `chat_router_goods_action.py` 於 `_compose_structured_reply()` 產生 `structured_payload.items` 與 `structured_products`，每筆包含 `商品編號/名稱/描述/購物連結` 等欄位。
- `/api/chat` 回應 JSON 中的 `structured_products` 為商品卡主要來源，前端 `sendChat()` 取得回應後寫入 `window.lastAssistantJson`，並透過 `latestSuggestCache[0/1]` 暫存，供 `switchToSearch()` 直接渲染商品卡。
- 若 `structured_products` 為空，前端會 fallback 至 `data.items` 或 `category_groups`；若仍無資料才顯示提示或重新觸發建議流程。

## 7. 「按 1 原建議」資訊流程
1. 使用者在聊天模式收到了包含 `structured_products` 的回覆；`sendChat()` 會呼叫 `setSuggestCache(1,…)/setSuggestCache(0,…)` 將商品清單與 ID 存進 `latestSuggestCache` 對應 slot。
2. `window.lastAssistantJson` 同步更新，可供 `original_suggestion_all.js` 解析 `structured_products` 或 `structured_payload.items` 取得補充 ID。
3. 當使用者點擊「1 原建議」按鈕時，事件監聽器會從 `latestSuggestCache[1]` 取出商品資料；若資料不足，才會回退到 `window.lastAssistantJson` 或 DOM 解析。
4. 一旦取得有效 ID，按鈕便透過 `/api/search` 重新載入商品卡或直接呼叫 `switchToSearch()` 切換顯示，完成原建議的復現。
