# 對話區模型路由設計方案

**撰寫日期：** 2025年11月11日  
**目的：** 在對話區中實現智能模型路由，根據使用者問題類型自動選擇使用商品搜尋模型或住宅維修模型

---

## 🎯 需求分析

目前系統有兩個對話模型：
1. **商品搜尋模型** - 現有的產品推薦和購物諮詢
2. **住宅維修模型** - 新增的維修問題診斷和建議（規劃中）

需要在前端對話區實現：
- ✅ 自動判斷使用者問題屬於哪個領域
- ✅ 路由到對應的後端 API 端點
- ✅ 顯示適當的回覆格式
- ✅ 使用者可手動切換模式

---

## 🏗️ 系統架構設計

### 整體架構

```
前端對話區
    ↓
意圖識別層（Frontend）
    ↓
    ├─ 商品相關 → /api/chat (現有)
    │              ↓
    │         商品搜尋服務
    │
    └─ 維修相關 → /api/repair/chat (新增)
                   ↓
              維修診斷服務
```

---

## 📋 實作方案

### 方案 A：前端意圖識別 + 路由（推薦）

#### 優點
- ✅ 回應速度快（不需額外 API 呼叫）
- ✅ 使用者體驗好（即時反饋）
- ✅ 減少後端負擔
- ✅ 易於擴展新模型

#### 實作步驟

**1. 前端新增意圖識別邏輯**

```javascript
// frontend/index.html

// 維修相關關鍵字
const REPAIR_KEYWORDS = [
  // 給排水
  '漏水', '滴水', '滲水', '水龍頭', '馬桶', '排水', '堵塞', '水管',
  // 電力
  '跳電', '斷電', '漏電', '插座', '電燈', '不亮', '閃爍',
  // 門窗
  '門鎖', '窗戶', '氣密', '滲水', '關不緊',
  // 冷氣
  '冷氣', '不冷', '滴水', '噪音', '震動',
  // 建築
  '壁癌', '裂縫', '地磚', '隆起',
  // 一般維修
  '維修', '修理', '故障', '壞掉', '報修', '師傅'
];

// 商品相關關鍵字
const SHOPPING_KEYWORDS = [
  '買', '購買', '訂購', '下單', '價格', '多少錢',
  '優惠', '特價', '折扣', '推薦', '哪裡買',
  '商品', '產品', '包包', '鞋子', '衣服'
];

/**
 * 識別使用者訊息的意圖
 * @param {string} message - 使用者訊息
 * @returns {'repair'|'shopping'|'unknown'} - 意圖類型
 */
function detectIntent(message) {
  const lowerMsg = message.toLowerCase();
  
  // 計算關鍵字匹配分數
  let repairScore = 0;
  let shoppingScore = 0;
  
  REPAIR_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) {
      repairScore++;
    }
  });
  
  SHOPPING_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) {
      shoppingScore++;
    }
  });
  
  // 根據分數判斷
  if (repairScore > shoppingScore && repairScore > 0) {
    return 'repair';
  } else if (shoppingScore > repairScore && shoppingScore > 0) {
    return 'shopping';
  }
  
  // 預設為商品搜尋（向後相容）
  return 'shopping';
}

/**
 * 根據意圖路由到對應的 API
 * @param {string} message - 使用者訊息
 * @param {string} intent - 意圖類型
 */
async function routeMessage(message, intent) {
  let endpoint;
  let requestBody;
  
  if (intent === 'repair') {
    // 路由到維修 API
    endpoint = buildBackendUrl('repair/chat');
    requestBody = {
      message: message,
      session_id: currentSessionId || null,
      history: chatHistory.slice(-10)
    };
  } else {
    // 路由到商品搜尋 API（現有）
    endpoint = buildBackendUrl('chat');
    requestBody = {
      message: message,
      session_id: currentSessionId || null,
      history: chatHistory.slice(-10)
    };
  }
  
  const resp = await fetch(endpoint, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(requestBody)
  });
  
  return await resp.json();
}
```

**2. 修改現有的 sendChat 函數**

```javascript
async function sendChatWithMessage(rawMessage, opts = {}) {
  const message = (rawMessage || "").trim();
  if (!message) return null;
  
  // 1. 意圖識別
  const intent = detectIntent(message);
  console.log(`🎯 檢測到意圖: ${intent}`);
  
  // 2. 顯示適當的載入狀態
  if (intent === 'repair') {
    setStatus('🔧 維修診斷中，請稍候…');
  } else {
    setStatus(getLoadingMessage(message));
  }
  
  // 3. 路由到對應的 API
  try {
    const data = await routeMessage(message, intent);
    
    // 4. 根據意圖渲染不同的回覆格式
    if (intent === 'repair') {
      renderRepairResponse(data);
    } else {
      renderShoppingResponse(data);
    }
    
    return data;
  } catch (err) {
    console.error('訊息處理失敗', err);
    appendChatBubble('assistant', '抱歉，系統暫時無法回應，請稍後再試。');
  }
}
```

/**

function renderRepairResponse(data) {
  if (!data || !data.reply) return;
  
  // 1. 顯示 AI 回覆
  appendChatBubble('assistant', data.reply);
  
  // 2. 如果有匹配的維修項目，顯示快速操作按鈕
  if (data.matched_repairs && data.matched_repairs.length > 0) {
    const repair = data.matched_repairs[0];
    
    // 顯示報修連結和影片連結
    const actionsHtml = `
      <div class="repair-actions">
        ${repair.page_url ? `
          <a href="${repair.page_url}" target="_blank" class="action-btn primary">
            📋 線上報修
          </a>
        ` : ''}
        ${repair.video_tutorial_url ? `
          <a href="${repair.video_tutorial_url}" target="_blank" class="action-btn secondary">
            🎥 觀看教學影片
          </a>
        ` : ''}
      </div>
    `;
    
    appendChatBubble('assistant', actionsHtml, { isHtml: true });
  }
  
  // 3. 顯示建議的後續問題
  if (data.suggestions && data.suggestions.length > 0) {
    const suggestionsHtml = data.suggestions
      .map(s => `<button class="suggestion-chip" onclick="sendQuickMessage('${s}')">${s}</button>`)
      .join('');
    appendChatBubble('assistant', suggestionsHtml, { isHtml: true });
  }
}

### 方案 B：後端統一路由（備選）

#### 架構

```
前端對話區
    ↓
POST /api/chat (統一入口)
    ↓
後端意圖識別服務
    ↓
    ├─ 商品意圖 → 商品搜尋服務
    └─ 維修意圖 → 維修診斷服務
```

#### 優點
- ✅ 前端實作簡單
- ✅ 意圖識別邏輯集中管理
- ✅ 可使用 LLM 進行更精準的意圖分類

#### 缺點
- ❌ 增加後端複雜度
- ❌ 多一次 API 呼叫延遲
- ❌ 需要更多後端資源

#### 實作概要

```python
# backend/app.py

@app.post("/api/chat", response_model=ChatResp)
def unified_chat_endpoint(req: ChatReq):
    """統一的聊天入口，自動路由到對應的處理器"""
    
    # 1. 意圖識別
    intent = detect_intent(req.message)
    
    # 2. 路由到對應的處理器
    if intent == 'repair':
        from repair_service import handle_repair_chat
        result = handle_repair_chat(req)
    else:
        # 現有的商品搜尋處理
        result = chat_handler(req)
    
    return result

def detect_intent(message: str) -> str:
    """使用關鍵字或 LLM 識別意圖"""
    repair_keywords = ['漏水', '維修', '故障', '壞掉', ...]
    
    # 簡單關鍵字匹配
    for keyword in repair_keywords:
        if keyword in message:
            return 'repair'
    
    # 或使用 LLM 進行精準分類
    # intent = llm_classify_intent(message)
    
    return 'shopping'
```
