# 連續維修第二筆失敗 - 快速診斷指南

> **問題：** 步驟1維修成功，步驟2維修失敗  
> **場景：** 瓦斯洩漏 → 插座發熱  
> **狀態：** ✅ 代碼已修復，需驗證

---

## 🎯 問題確認

### 測試場景
```
步驟 1: 瓦斯洩漏  → ✅ 維修成功
步驟 2: 插座發熱  → ❌ 失敗（應該維修）
```

### 問題根源
- ✅ **已識別**：步驟 1 的回應包含 `alignment` 欄位
- ✅ **已識別**：步驟 2 保留歷史，將 `alignment` 發送到後端
- ✅ **已識別**：後端 `List[Dict[str, str]]` 不允許非字串值
- ✅ **已修復**：添加了 `cleanHistory` 過濾邏輯

---

## 🔍 快速診斷步驟

### 步驟 1：確認修復代碼已載入

打開瀏覽器開發者工具（F12），在 **Console** 執行：

```javascript
// 檢查是否有清理邏輯
const code = document.documentElement.innerHTML;
const hasCleanHistory = code.includes('cleanHistory');
console.log('✅ 修復代碼已載入:', hasCleanHistory);

// 如果返回 false，需要強制刷新
if (!hasCleanHistory) {
    console.log('❌ 修復未載入，請按 Cmd+Shift+R 強制刷新');
}
```

### 步驟 2：執行測試序列

依序輸入（清空對話後重新開始）：

1. **步驟 1**：`瓦斯洩漏`
2. **步驟 2**：`插座發熱`

### 步驟 3：觀察 Console 日誌

#### ✅ 成功的日誌應該包含：

```
步驟 1:
🎯 [Intent] 意圖分析: detected=repair
🔧 [Route] 路由到維修服務
➡️ [Intent] 意圖延續: repair，保留歷史 (0 條)

步驟 2:
🎯 [Intent] 意圖分析: detected=repair
✅ [Intent] 意圖持續: repair
🔧 [Route] 路由到維修服務
➡️ [Intent] 意圖延續: repair，保留歷史 (2 條)
```

#### ❌ 失敗的日誌會包含：

```
步驟 2:
🔧 [Route] 路由到維修服務
❌ [Route] 維修服務錯誤，降級到商品搜尋: Error: HTTP 422
🆕 [Intent] 強制清空歷史（降級或重試）
🛒 [Route] 路由到商品搜尋
```

## 🔧 如果仍然失敗

### 原因 1：瀏覽器緩存未更新

**解決方法：**
1. 按 `Cmd + Shift + R`（macOS）或 `Ctrl + Shift + R`（Windows）強制刷新
2. 或打開開發者工具 → Network 標籤 → 勾選 "Disable cache"

### 原因 2：代碼未正確載入

**檢查方法：**
1. 打開開發者工具 → **Sources** 標籤
2. 找到 `frontend/index.html`
3. 搜尋 `cleanHistory`（Cmd+F）
4. 確認代碼中有以下內容：

```javascript
// ✅ 清理歷史記錄，移除額外欄位（如 alignment）
const cleanHistory = payloadHistory.map(msg => ({
  role: msg.role,
  content: msg.content
}));
```

### 原因 3：後端問題

**檢查後端日誌：**
```bash
# 查看後端終端輸出
# 尋找類似的錯誤訊息：
[ERROR] Validation error: ...
[ERROR] 422 Unprocessable Entity
```
