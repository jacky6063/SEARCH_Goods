# 語音模式整合設計（僅限商品查詢 / 公司資料查詢）

## 1. 目的與範圍
- 讓既有 LLM 查詢管線提供「語音輸入 + 語音輸出」體驗，目前 **僅限商品查詢與公司資料查詢** 兩種模板；其餘待日後評估，需列入語音模式擴展待辦清單（例：售後詢問、活動資訊等）。
- 使用語音流程時，必須跟文字模式共享同一份 LLM 溝通邏輯，避免演變為開放式聊天機器人。
- 本文件定義：前端操作方式、後端管線調整、啟停條件、以及錯誤/例外回覆策略，並新增管理後台的語音開關與隱私義務。

## 2. 高階流程
1. **語音入口提示**：使用者按下「語音模式」前，前端顯示「僅支援商品/公司查詢」提醒。
2. **語音啟動**：前端取得麥克風授權並使用 MediaRecorder 錄製 `audio/webm`，結束後一次性送至 `/api/voice/transcribe`（Whisper）。
3. **意圖雙重判斷**：  
   - 前端先做一次簡易分類（例如關鍵字或輕量模型）；非合法意圖則即時播放提示並拒絕啟用。  
   - 後端 LLM/intent parser 在每回合檢查意圖；若偏離允許列表，回覆固定訊息並要求前端結束語音。
4. **LLM 查詢**：沿用既有 `goods_search_service` 或 `company_profile_service` 流程。
5. **語音回覆**：後端回傳文字 + `voice_directives`。前端將文字轉為 TTS 播放，並在收到 `voice_mode_active=false` 後自動關閉麥克風。
6. **結果呈現**：商品或公司資料卡出現在畫面，同步進行簡短語音摘要。

## 3. 系統設計

### 3.1 前端組件
- **語音控制器 (`voiceController`)**：封裝 MediaRecorder 生命週期、錄音長度限制（25 秒）、自動停止以及上傳流程。錄完後呼叫 `/api/voice/transcribe`，再把辨識文字交給共用 `sendChatWithMessage(voiceMode=true)`。
- **TTS 播放器**：使用瀏覽器 `speechSynthesis`，朗讀後端提供的 `voice_summary`，並依 `voice_mode_active` / `voice_session_end` 切換回文字。
- **UI 與狀態**：語音按鈕僅在 `_branding.voice_mode_enabled` 且瀏覽器支援 MediaRecorder 時顯示；錄音中加上 `recording` 樣式，狀態列顯示「正在錄音 / 語音辨識中」等提示。
- **管理面板開關**：僅保留 `voice_mode_enabled` checkbox。儲存後會即時同步 `_branding` 與語音按鈕狀態；其餘 STT 供應商設定已移除。

### 3.2 後端流程調整
- **語音會話控制**（以 `voice_service.py` + `chat_endpoint` 完成）：
  1. 驗證 `allowed_intents`，若空或不符直接返回錯誤碼。
  2. 對每次語音轉文字的查詢執行既有意圖判斷，若意圖不在白名單，回覆：
     ```
     目前語音模式僅支援商品或公司資料查詢，已為您關閉語音模式，請改用文字輸入。
     ```
     並在 payload 中設定 `voice_mode_active=false`。
  3. 若查詢合法，呼叫對應服務並於 payload 中附上：
     - `results` / `structured_products`
     - `voice_summary`: 用於 TTS 的精簡摘要
     - `voice_mode_active` / `voice_session_end`: 控制前端是否繼續錄音
- **Session 結束信號**：以 `voice_session_end: true` 或 `voice_mode_active: false` 告知前端自動收麥。
- **Fallback 回覆**：若沒有結果，統一回覆「暫時找不到符合條件的項目...」，同時保持 `voice_mode_active=true` 讓使用者可直接再次錄音。

### 3.3 提示詞/LLM 規範
- 在系統提示中加入：
  1. 語音模式僅允許上述兩種任務。
  2. 回覆格式：先 1 句摘要，再列出 2~3 個重點，語氣友善但簡潔。
  3. 當查詢無效或超出範圍，使用固定句型並請求前端關閉語音。

### 3.4 語音資料與隱私
- 不保存任何語音錄音或原始音檔，僅保留 Whisper 輸出的文字於當回合使用。
- 後端在 `_read_audio_bytes` 先驗證格式與大小（<= 5MB 約 30 秒），拒絕超時音訊。
- UI 顯示「語音資料僅即時轉文字，不留錄音」提示，隱私條款需同步更新。
- 後端不得將語音資料寫入 log；必要的除錯資訊請以匿名化的文字呈現。

## 4. 操作方式

### 4.1 使用者操作
1. 按下「語音輸入」按鈕（或 `Ctrl/Cmd+Shift+S` 快捷鍵）開始錄音，狀態列顯示「🎙️ 正在錄音」。
2. 說出商品或公司需求（例：「幫我找 3000 元以上的女用包」）。
3. 錄音結束後會自動上傳至 `/api/voice/transcribe`；辨識結果填回輸入框並立即觸發 `sendChatWithMessage(..., voiceMode=true)`。
4. 後端回覆帶有 `voice_summary` 時會以 SpeechSynthesis 播放；收到 `voice_mode_active=false` 或 `voice_session_end=true` 時自動結束語音模式。

### 4.2 後台/開發者操作
1. 前端：只需確認 `voice_mode_enabled` 為 true 且瀏覽器支援 MediaRecorder / SpeechSynthesis，無需額外 STT Key。
2. 後端：`voice_service.py` 依賴環境變數 `OPENAI_API_KEY`，無需再設定 Google/Azure。`/api/voice/transcribe` 與 `/api/voice/chat` 均在 `app.py` 內完成。
3. 部署：確認 Render / Netlify 等環境設定 `OPENAI_API_KEY`，其餘語音服務欄位暫不使用。
4. 監控：新增 voice-session 指標（啟用次數、拒絕次數、平均時長、成功率），以便後續優化提示與邏輯。
5. 管理後台：新增「語音模式」設定頁，提供 `voice_mode_enabled` 開關與 STT/TTS 服務配置欄位；上線初期預設關閉，待成本評估完成後再啟用。

## 5. 例外與錯誤處理
- **語音授權失敗**：前端直接提示「無法取得麥克風，請檢查瀏覽器設定」，不發送請求。
- **意圖不支援**：後端返回 `voice_mode_active=false` + 固定提示，並記錄事件。
- **LLM 回覆延遲**：前端顯示載入動畫，同時播放「正在為您查找，請稍候」的語音。
- **多輪切換**：若使用者在語音中要求改用文字，LLM 回覆中加入指示（`switch_to_text=true`），前端即顯示文字輸入框並停用語音。
