# 聊天紀錄資料表設計

本文件描述統一聊天紀錄方案的 Schema 設計，適用於目前的三個模組（商品查詢、公司資料查詢、住宅維修客服）。核心目標：

1. 清楚區分對話狀態與模組來源，方便稽核與後續模型分析。
2. 在 Supabase Postgres 中建置可延展的結構，納入 Realtime 監控及 RLS 安全控管。
3. 對商品模組特別保留 LLM 推薦結果（僅商品編號與名稱），以供推薦品質追蹤與模型優化。

---

## 資料表用途

- **`chat_sessions`**：統一記錄一次對話的生命周期（模組、狀態、渠道、公司別資訊與上下文），並與 `chat_messages`、`product_recommendations`、`session_events` 透過 `session_id` 關聯。
- **`chat_messages`**：保存所有訊息（使用者、LLM、客服等）與原始 payload，用於還原對話與訓練資料萃取；`session_id` 指向 `chat_sessions`，`message_id` 供 `product_recommendations` 使用。
- **`product_recommendations`**：針對商品模組紀錄 LLM 推薦的商品編號與名稱，衡量推薦行為成效，並透過 `session_id`、`message_id` 連回主體資料。
- **`session_events`（選配）**：紀錄狀態轉換與異常事件的時間序列，方便監控或追蹤歷史；以 `session_id` 對應 `chat_sessions`。

---

## 詳細欄位設計

### 1. `chat_sessions`

- `session_id`：UUID PK，作為全域唯一對話識別。
- `module_type`：ENUM(`goods`,`company`,`repair`) NOT NULL，說明對話所屬模組。
- `user_id`：UUID/VARCHAR，使用者或匿名 token（可為 `NULL`）。
- `company_code`：VARCHAR，代表企業/品牌代碼，支援多租戶切分。
- `company_name`：VARCHAR，顯示用公司名稱，方便營運查詢。
- `status`：ENUM(`ongoing`,`resolved`,`escalated`,`expired`)，紀錄目前進度。
- `started_at`：TIMESTAMPTZ DEFAULT now()，對話建立時間。
- `ended_at`：TIMESTAMPTZ，對話結束時間。
- `channel`：VARCHAR，來源渠道（web、app、ivr 等）。
- `context_tags`：TEXT[]，標記關鍵流程或意圖（如 price_filter）。
- `metadata`：JSONB，額外資訊（語言、裝置、區域等）。

**索引與治理**
- 索引 `(module_type, started_at)`、`(user_id, status)`。
- RLS 依 `user_id` 或 service token 控制讀寫。
- 需定期排程（例如 90 天）做資料留存與匿名化。

### 2. `chat_messages`

- `message_id`：BIGSERIAL PK，對應單則訊息。
- `session_id`：UUID FK→`chat_sessions`，指定訊息所在對話。
- `role`：ENUM(`user`,`llm`,`agent`,`system`)，標註發話角色。
- `content`：TEXT，實際呈現給前端的文字內容。
- `payload`：JSONB，原始資料（如語音轉文字、信心值）。
- `created_at`：TIMESTAMPTZ DEFAULT now()，訊息建立時間。
- `source_module`：ENUM 同 `module_type`，冗餘欄位以利查詢。
- `state`：ENUM(`received`,`processed`,`error`)，紀錄訊息流程狀態。

**索引與治理**
- 索引 `(session_id, created_at)`、`(role)`。
- 若內容含敏感資訊，於 `payload` 做欄位遮罩或分層權限。

### 3. `product_recommendations`

- `rec_id`：BIGSERIAL PK，推薦紀錄識別。
- `session_id`：UUID FK→`chat_sessions`，對應的對話。
- `message_id`：BIGINT FK→`chat_messages`，對應 LLM 回覆訊息。
- `product_id`：VARCHAR NOT NULL，商品編號。
- `product_name`：VARCHAR NOT NULL，商品名稱。
- `source_rank`：SMALLINT，推薦順位。
- `confidence`：NUMERIC(5,2)，模型信心值（可選）。
- `logged_at`：TIMESTAMPTZ DEFAULT now()，紀錄時間。

**索引與治理**
- UNIQUE(`message_id`, `product_id`) 防止重複紀錄。
- 索引 `product_id`、`(session_id, logged_at)` 方便查詢曝光量與時序。
- 可再串接下游交易資料衡量轉換。

### 4. `session_events`（選配）

- `event_id`：BIGSERIAL PK，事件識別。
- `session_id`：UUID FK→`chat_sessions`，所屬對話。
- `event_type`：ENUM(`status_change`,`handoff`,`error`)，事件類型。
- `from_status`：ENUM 同 `status`，變更前狀態。
- `to_status`：ENUM 同 `status`，變更後狀態。
- `details`：JSONB，事件補充說明。
- `created_at`：TIMESTAMPTZ DEFAULT now()，事件發生時間。

**應用情境**
- 供營運監控與告警；例如 `error` 類型可觸發 PagerDuty。
- 也能作為對話流程 A/B 測試的事件流紀錄。

---

## 後續應用建議

1. **模型優化資料集**：從 `chat_messages` 抽樣貼到標註系統，並利用 `chat_sessions` 的 `module_type` 與 `status` 篩出高優先場景。
2. **推薦成效**：以 `product_recommendations` 搭配外部轉換資料，計算曝光、點擊、成交率，反饋給 LLM prompt 或 reranker。
3. **營運監控**：`session_events` 提供狀態流轉時間，建立報表監控 escalated/expired 比例，及早調整流程。
4. **安全治理**：在 Supabase 設定 Row Level Security，並針對含 PII 的欄位（例如 `user_id`、`metadata`）實施加密或 tokenization。

> 待實作 Logging SDK 時，可依本資料表定義介面：`start_session`、`append_message`、`log_recommendations`、`log_session_event`，確保三個模組接入時一致且可觀測。

---

## 建議 SQL Schema

```sql
create type module_type as enum ('goods', 'company', 'repair');
create type chat_status as enum ('ongoing', 'resolved', 'escalated', 'expired');
create type message_role as enum ('user', 'llm', 'agent', 'system');
create type message_state as enum ('received', 'processed', 'error');
create type session_event_type as enum ('status_change', 'handoff', 'error');

create table if not exists chat_sessions (
    session_id     uuid primary key default gen_random_uuid(),
    module_type    module_type not null,
    user_id        text,
    company_code   text,
    company_name   text,
    status         chat_status not null default 'ongoing',
    started_at     timestamptz not null default now(),
    ended_at       timestamptz,
    channel        text,
    context_tags   text[],
    metadata       jsonb default '{}'::jsonb
);

create index if not exists idx_chat_sessions_module_started
    on chat_sessions (module_type, started_at desc);
create index if not exists idx_chat_sessions_user_status
    on chat_sessions (user_id, status);
create index if not exists idx_chat_sessions_company
    on chat_sessions (company_code, started_at desc);

create table if not exists chat_messages (
    message_id     bigserial primary key,
    session_id     uuid not null references chat_sessions(session_id) on delete cascade,
    role           message_role not null,
    content        text,
    payload        jsonb default '{}'::jsonb,
    created_at     timestamptz not null default now(),
    source_module  module_type,
    state          message_state not null default 'received'
);

create index if not exists idx_chat_messages_session_time
    on chat_messages (session_id, created_at);
create index if not exists idx_chat_messages_role
    on chat_messages (role);

create table if not exists product_recommendations (
    rec_id         bigserial primary key,
    session_id     uuid not null references chat_sessions(session_id) on delete cascade,
    message_id     bigint not null references chat_messages(message_id) on delete cascade,
    product_id     text not null,
    product_name   text not null,
    source_rank    smallint,
    confidence     numeric(5,2),
    logged_at      timestamptz not null default now()
);

alter table product_recommendations
    add constraint uq_product_recs_message_product
    unique (message_id, product_id);
create index if not exists idx_product_recs_product
    on product_recommendations (product_id);
create index if not exists idx_product_recs_session_time
    on product_recommendations (session_id, logged_at);

create table if not exists session_events (
    event_id       bigserial primary key,
    session_id     uuid not null references chat_sessions(session_id) on delete cascade,
    event_type     session_event_type not null,
    from_status    chat_status,
    to_status      chat_status,
    details        jsonb default '{}'::jsonb,
    created_at     timestamptz not null default now()
);

create index if not exists idx_session_events_session_time
    on session_events (session_id, created_at);
```

> 若環境已定義相同 ENUM，可直接重複使用；Supabase 上可透過 migration script 或 SQL Editor 執行上述語法。
