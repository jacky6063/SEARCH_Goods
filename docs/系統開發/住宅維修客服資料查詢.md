## 需求概述

建立一個住宅維修客服對話記錄查詢頁面，讓操作者可以按日期查詢當天的所有維修諮詢對話，並以清晰的格式檢視使用者問題與系統回覆。

**核心目標**：
- ✅ 快速查詢指定日期的維修對話記錄
- ✅ 最新對話優先顯示（最後詢問者資料在前）
- ✅ 會話分組清晰，保持對話脈絡
- ✅ 與現有系統無縫整合

---

## 功能需求

### 查詢條件
- **日期選擇器**：預設今天，格式 YYYY-MM-DD
- **查詢範圍**：指定日期 00:00:00 ~ 23:59:59
- **篩選條件**：`source_module = 'repair'`

### 資料顯示

#### 顯示欄位
- `message_id`：訊息編號
- `session_id`：會話識別（前 8 碼）
- `role`：user（使用者）/ llm（系統）
- `content`：對話內容
- `created_at`：時間戳記

#### 排序邏輯（v1.4）
```
後端：ORDER BY created_at DESC（最新訊息在前）
前端：
  1. 按 session_id 分組
  2. 組內按 created_at ASC 排序（保持對話順序）
  3. 會話按最後訊息時間排序（最新會話在前）
```

#### 統計資訊
- 總訊息數（total_count）
- 使用者訊息數（user_count）
- 系統回覆數（llm_count）
- 會話數（session_count）

### 後端 API

**端點**：`GET /api/repair/chat_logs`  
**檔案**：`backend/app.py` (line 1830-1922)

**參數**：
- `date` (required): 查詢日期 YYYY-MM-DD

**實作**：
```python
# 時間範圍
start_time = target_date.replace(hour=0, minute=0, second=0, microsecond=0)
end_time = start_time + timedelta(days=1)

# Supabase 查詢
response = client.table('chat_messages')\
    .select('message_id, session_id, role, content, created_at')\
    .eq('source_module', 'repair')\
    .gte('created_at', start_time.isoformat())\
    .lt('created_at', end_time.isoformat())\
    .order('created_at', desc=True)\
    .execute()
```

**回應格式**：
```json

  "session_count": 4,

}
```

- **Commit**：74a04b1
- **問題**：硬編碼 `http://localhost:8000` 導致生產環境 404

#### 修正 #2：Supabase 參數（v1.3）
- **Commit**：da21ab2
- **問題**：`order('created_at', asc=True)` 參數錯誤
- **解決**：改為 `order('created_at', desc=False)`
- **原因**：Supabase Python 客戶端只接受 `desc` 參數

#### 修正 #3：排序邏輯（v1.4）
- **Commit**：5bc7ca5
- **需求**：最後詢問者資料往前排列
- **調整**：後端 `created_at DESC` + 前端會話分組排序
- **效果**：最新對話優先，保持脈絡清晰
