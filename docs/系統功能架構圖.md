# SEARCH_Goods 功能架構圖

## 系統總覽
- 目標：提供「聊天式商品搜尋 + 推薦」的一站式體驗，串接 CSV 目錄、LLM 推理與 Netlify 前端。
- 特色：單一 FastAPI 後端，集中處理查詢解析、LLM 對話、商品搜尋與行政維運。

## 細項功能區塊

### 1. Frontend SPA（Netlify 部署）
- **聊天互動**：與 `/api/chat` 對接，處理使用者輸入、顯示推薦卡片、提供按鍵互動（如「顯示建議」）。
- **搜尋結果頁/靜態頁**：載入 Render 後端的靜態資源或 API，展示商品細節。
- **管理入口**：提供 CSV 上傳與快取清除的表單（需 `ADMIN_TOKEN`）。

### 2. API 層（FastAPI）
- **路由**：`backend/app.py` 定義 `/api/chat`, `/api/search`, `/api/suggest`, `/api/admin/*` 等端點。
- **中介層功能**：CORS、環境偵測、版本資訊（BUILD_COMMIT/BRANCH）、靜態檔案服務。
- **資料存取**：透過 `config_store`, `catalog_service` 讀取設定與商品快照；`bundle_service` 管理對話快取。

### 3. Chat Router & LLM Flow
- **意圖管線**：`chat_router_goods_action.py` 組合 Planner、Fallback、多模態模式，並強制導入 LLM `chat_reply`。
- **LLM 服務**：`llm_service.py` 處理 query 擴展、分類層級解析、價格/類別結構化過濾、Mock LLM fallback。
- **模式切換**：依 `intent` 決定資訊回覆、推薦導購、活動企劃等模式，並寫入 `structured_payload`、`action`。

### 4. 搜尋與推薦核心
- **`goods_search_service.py`**：載入 `VIEW_GOODS_enhanced.csv`、正規化欄位、執行向量/關鍵字搜尋、格式化結果。
- **`search_ext_goods_1024001.py`**：強化版篩選（鞋/包語意、價格範圍、排除詞），並與 LLM 提供的過濾條件結合。
- **推薦模式**：`modes/shopping_recommender.py`、`modes/marketing_consultant.py` 根據 LLM alignment、Planner 產出建議。
- **FieldAccessor**：統一欄位存取（中英欄位映射、價格/描述標準化），避免 CSV 欄位差異導致錯誤。

### 5. 服務協作層
- **`catalog_service`**：商品快照管理、以 ID 查找商品，供聊天結果/Planner 使用。
- **`bundle_service`**：快取 align 結果、結構化 payload、session 對話，以利二次顯示。
- **`categories_service`**：提供分類診斷/階層資訊，支援 L1/L2/L3 導覽。

### 6. 資料層 & 管理
- **資料來源**：`data/VIEW_GOODS_enhanced.csv` 為主要商品表；`update_csv.py` 支援 ETL 更新。
- **配置**：`.env`、`config_store.py` 保存品牌字詞、LLM 切換開關、TTL 設定。
- **日誌/快取**：`server.log`、`bundle_service` 內存快取，並有 session cleanup 邏輯。
- **管理端點**：`/api/admin/upload-csv`, `/api/admin/clear-cache` 需 `ADMIN_TOKEN`；`scripts/setup.sh`/`smoke_test.sh` 輔助維運。

### 7. CI/CD 與部署
- **CI**：`.github/workflows/ci.yml` 在 PR/push 時執行 pytest；`smoke.yml`、`deploy.yml` 處理 Smoke Test 與部署。
- **部署目標**：後端 Render（Gunicorn / Uvicorn）、前端 Netlify。`Dockerfile`、`docker-compose*.yml` 支援本地與雲端環境。
- **自動化腳本**：`scripts/smoke_test.sh`, `scripts/setup.sh`，快速驗證與建置。

## 使用說明
- 若需擴充欄位或資料結構，優先更新 `backend/column_definitions.json` 與 `FieldAccessor.FIELD_MAPPINGS`，保持前後一致。
- 若需新增聊天模式或推薦邏輯，從 `chat_router_goods_action.py` 進入，將新的 handler 接至 `modes/*` 或 Planner。
- 當 CSV 來源變動，透過 Admin API 或 `update_csv.py` 更新檔案，並重新載入快取以確保搜尋一致性。
