## 2025-10-23 — Chat Mode ⇄ Search Mode 整合任務卡

### 任務摘要
- 扩充現有系統，讓 **聊天模式（Chat Mode）** 支援自然語言互動並回傳多組商品群組。
- 切換到 **商品模式（Search Mode）** 時，必須自動載入並顯示聊天模式找出的全部商品，維持兩種模式資料一致。

### 前端需求重點
1. **ChatView**
   - 聊天視窗顯示 `groups[]` 分群結果，每組需有分類標題與商品卡。
   - 若僅有 `items[]`，沿用單組商品卡顯示。
   - 提供「切換至商品模式」按鈕，並保留存在的語音、重置功能。
2. **SearchView**
   - 接收聊天模式回傳的所有商品（多群組合併後清單）。
   - 切換後自動呈現 10 項商品（例示：餅乾 3 + 飲料 3 + 休閒食品 4）。
   - 仍需保留原有搜尋欄位、篩選與排序行為。

### 後端需求重點
- 新增或擴充 `/api/chat-search` 以支援自然語言解析並回傳統一格式：
  ```json
  {
    "reply": "…",
    "groups": [
      {"category": "餅乾類", "items": [...]},
      {"category": "飲料類", "items": [...]}
    ],
    "related_queries": ["..."]
  }
  ```
- 單群組情境以 `items[]` 回傳。
- 查無結果時提供提示訊息與 `related_queries` 建議。
- 資料來源固定為 `VIEW_GOODS.csv`，需運用欄位：`GoodIden`, `Name`, `Description`, `Price`, `SpecialOffer`, `Category`, `Goods_link1`, `Goodspic_link1`。

### 驗收與體驗指標
| 項目 | 期待結果 |
| --- | --- |
| 聊天畫面 | 支援多群組顯示，含分類標題與商品卡 |
| 商品模式 | 切換後自動顯示聊天結果的全部商品（合併列表） |
| API | 回傳 `reply + groups/items + related_queries` 結構正確 |
| 錯誤處理 | 查無結果時提供提示與相關建議 |
| 資料一致性 | 兩種模式顯示的商品內容一致 |
| 效能 | 模式切換延遲 < 2 秒 |
