## 🔍 發現的問題

### ❌ 問題 1: `detectIntent` 在已鎖定時仍返回鎖定模式，但邏輯有誤

**位置**: `frontend/index.html` 行 1643-1689

**問題描述**:
```javascript
function detectIntent(message) {
  const manualLocked = intentModeLock === 'manual' && currentIntentMode !== 'auto';
  const systemLocked = intentModeLock === 'system' && currentIntentMode !== 'auto';
  if (manualLocked || systemLocked) {
    return currentIntentMode;  // ✅ 這裡正確
  }
  
  // ... 關鍵字評分邏輯 ...
  
  // 判定意圖
  if (repairScore > shoppingScore && repairScore > 0) {
    if (currentIntentMode === 'auto') {
      setIntentMode('repair', 'auto-detect');  // ⚠️ 這裡會鎖定
    }
    return 'repair';
  } else if (shoppingScore > repairScore && shoppingScore > 0) {
    return 'shopping';  // ❌ 問題：沒有鎖定 shopping 模式
  }
  
  // 預設為商品搜尋（向後相容）
  return 'shopping';  // ❌ 問題：預設也沒有鎖定
}
```

**問題分析**:
1. ✅ 當檢測到 `repair` 意圖時，會自動鎖定為 `repair` 模式
2. ❌ 當檢測到 `shopping` 意圖時，**沒有鎖定** `shopping` 模式
3. ❌ 預設返回 `shopping` 時，也**沒有鎖定**

**結果**: 
- 使用者輸入維修問題 → 系統鎖定為維修 ✅
- 使用者追問「還有其他方案嗎？」→ 沒有維修或商品關鍵字 → 返回 `shopping` 但**沒有解鎖維修模式** ❌
- 由於 `intentModeLock = 'system'` 且 `currentIntentMode = 'repair'`，下次 `detectIntent` 會直接返回 `repair` ✅
- **BUT**: 如果追問時包含商品關鍵字（如「有便宜一點的嗎？」），會返回 `shopping` 但維修鎖定依然存在 ❌

### ❌ 問題 2: `routeMessageByIntent` 的意圖切換檢測有缺陷

**位置**: `frontend/index.html` 行 1697-1764

**問題描述**:
```javascript
async function routeMessageByIntent(message, intent, options = {}) {
  // 🔄 檢測意圖切換
  let lastIntent = null;
  if (chatHistory.length > 0) {
    // 查找最後一條使用者訊息
    for (let i = chatHistory.length - 1; i >= 0; i--) {
      if (chatHistory[i].role === 'user') {
        lastIntent = detectIntent(chatHistory[i].content);  // ❌ 問題在這裡
        break;
      }
    }
  }
  
  const intentChanged = lastIntent && lastIntent !== intent;
  
  // 如果意圖切換，清空歷史避免干擾
  const payloadHistory = intentChanged ? [] : chatHistory.slice(-10);
}
```

**問題分析**:
1. ❌ `detectIntent(chatHistory[i].content)` 使用**歷史訊息**來檢測意圖
2. ❌ 但 `detectIntent` 會檢查 `intentModeLock`，如果已鎖定，會直接返回 `currentIntentMode`
3. ❌ 這導致 `lastIntent` **永遠等於** `currentIntentMode`（在鎖定狀態下）
4. ❌ 所以 `intentChanged` **永遠是 false**
5. ❌ 即使使用者從維修切換到商品，對話歷史也不會被清空

**預期行為**:
- 應該根據**實際的訊息內容**判斷意圖，而不是受鎖定狀態影響

**位置**: 多處

**問題描述**:

- 商品模式沒有任何保護，容易被維修關鍵字干擾

### ⚠️ 問題 4: `setIntentMode` 的 source 參數使用不當

**位置**: `frontend/index.html` 行 1606-1634

**問題描述**:
```javascript
function setIntentMode(mode, reason = '', source = 'system') {
  // ...
  const manualLocked = prevLock === 'manual' && prevMode !== 'auto';
  if (manualLocked && source !== 'manual' && mode !== 'auto') {
    console.log(`🔒 [Intent] 手動鎖定 ${prevMode}，忽略切換至 ${mode}`);
    return;  // ✅ 防止系統覆蓋手動鎖定
  }
  
  currentIntentMode = mode;
  if (mode === 'auto') {
    intentModeLock = 'auto';  // ✅ 解除鎖定
  } else if (source === 'manual') {
    intentModeLock = 'manual';  // ✅ 手動鎖定
  } else {
    intentModeLock = 'system';  // ⚠️ 系統鎖定
  }
}
```

**問題分析**:
1. ✅ 手動鎖定（manual）可以防止系統覆蓋
2. ⚠️ 系統鎖定（system）和無鎖定（auto）在 `detectIntent` 中被區別對待
3. ❌ 但在多處呼叫 `setIntentMode` 時，都使用預設的 `source = 'system'`
4. ❌ 這導致一旦系統鎖定，就需要明確的**手動操作**或**reset**才能解除

**目前呼叫情況**:
- `detectIntent`: `setIntentMode('repair', 'auto-detect')` → source='system' ✅
- `routeMessageByIntent`: `setIntentMode('repair', 'route-repair')` → source='system' ✅
- 回應渲染: `setIntentMode('repair', 'response-flag')` → source='system' ✅
- 手動按鈕: `setIntentMode('repair', 'manual', 'manual')` → source='manual' ✅
- Reset: `setIntentMode('auto', 'reset')` → source='system' ⚠️

**潛在問題**: 
- `reset` 時 source='system'，但目標是 `mode='auto'`，所以會正確設定 `intentModeLock='auto'` ✅

## 💡 建議修復方案

### 修復 1: 統一鎖定邏輯

**原則**: 
- ✅ **只在首次檢測到意圖時鎖定**
- ✅ **鎖定後的追問保持在同一模式**
- ✅ **明確的意圖切換應該解除鎖定並重新鎖定新意圖**

**建議實作**:

```javascript
function detectIntent(message) {
  const manualLocked = intentModeLock === 'manual' && currentIntentMode !== 'auto';
  if (manualLocked) {
    return currentIntentMode;
  }
  
  // 計算分數
  let repairScore = 0;
  let shoppingScore = 0;
  REPAIR_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) repairScore++;
  });
  SHOPPING_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) shoppingScore++;
  });
  
  // 🆕 改進：明確的意圖切換檢測
  let detectedIntent = 'shopping'; // 預設
  if (repairScore > shoppingScore && repairScore > 0) {
    detectedIntent = 'repair';
  } else if (shoppingScore > repairScore && shoppingScore > 0) {
    detectedIntent = 'shopping';
  }
  
  console.log('🎯 [Intent] 意圖分析:', {
    message: message.substring(0, 50),
    repairScore,
    shoppingScore,
    detected: detectedIntent,
    current: currentIntentMode,
    lock: intentModeLock
  });
  
  // 🆕 改進：只在 auto 模式且意圖明確時鎖定
  if (currentIntentMode === 'auto') {
    if (repairScore > 0 || shoppingScore > 0) {
      // 有明確意圖，鎖定
      setIntentMode(detectedIntent, 'auto-detect', 'system');
    }
  } else if (intentModeLock === 'system') {
    // 🆕 改進：檢測意圖切換
    if (detectedIntent !== currentIntentMode) {
      // 意圖明確切換（需要有關鍵字）
      if ((detectedIntent === 'repair' && repairScore > 0) ||
          (detectedIntent === 'shopping' && shoppingScore > 0)) {
        console.log(`🔄 [Intent] 檢測到意圖切換: ${currentIntentMode} → ${detectedIntent}`);
        setIntentMode(detectedIntent, 'intent-switch', 'system');
      }
    }
  }
  
  return intentModeLock === 'system' ? currentIntentMode : detectedIntent;
}
```

### 修復 2: 改進 `routeMessageByIntent` 的歷史意圖檢測

**問題**: 使用 `detectIntent(舊訊息)` 會受鎖定狀態影響

**建議**: 建立一個純粹的意圖檢測函式

```javascript
// 🆕 新增：純粹的意圖檢測（不受鎖定狀態影響）
function detectIntentPure(message) {
  let repairScore = 0;
  let shoppingScore = 0;
  REPAIR_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) repairScore++;
  });
  SHOPPING_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) shoppingScore++;
  });
  
  if (repairScore > shoppingScore && repairScore > 0) {
    return 'repair';
  } else if (shoppingScore > repairScore && shoppingScore > 0) {
    return 'shopping';
  }
  return 'shopping';
}

async function routeMessageByIntent(message, intent, options = {}) {
  // 🆕 改進：使用純粹檢測
  let lastIntent = null;
  if (chatHistory.length > 0) {
    for (let i = chatHistory.length - 1; i >= 0; i--) {
      if (chatHistory[i].role === 'user') {
        lastIntent = detectIntentPure(chatHistory[i].content);  // ✅ 使用純粹檢測
        break;
      }
    }
  }
  
  const intentChanged = lastIntent && lastIntent !== intent;
  const payloadHistory = intentChanged ? [] : chatHistory.slice(-10);
  
  if (intentChanged) {
    console.log(`🔄 [Intent] 意圖切換: ${lastIntent} → ${intent}，清空對話歷史`);
  }
  
  // ... 其餘邏輯不變
}
```

### 修復 3: 增強追問時的意圖重檢測

**建議**: 在每次訊息時都重新評估意圖，但要有門檻

```javascript
function detectIntent(message) {
  const manualLocked = intentModeLock === 'manual' && currentIntentMode !== 'auto';
  if (manualLocked) {
    return currentIntentMode;
  }
  
  // 計算分數
  let repairScore = 0;
  let shoppingScore = 0;
  REPAIR_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) repairScore++;
  });
  SHOPPING_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) shoppingScore++;
  });
  
  let detectedIntent = 'shopping';
  if (repairScore > shoppingScore && repairScore > 0) {
    detectedIntent = 'repair';
  } else if (shoppingScore > repairScore && shoppingScore > 0) {
    detectedIntent = 'shopping';
  }
  
  // 🆕 改進：追問時的強意圖切換
  if (intentModeLock === 'system' && currentIntentMode !== 'auto') {
    // 已鎖定，但檢測到強烈的相反意圖
    const strongOppositeIntent = 
      (currentIntentMode === 'repair' && shoppingScore >= 2) ||  // 至少2個商品關鍵字
      (currentIntentMode === 'shopping' && repairScore >= 2);   // 至少2個維修關鍵字
    
    if (strongOppositeIntent) {
      console.log(`🔄 [Intent] 強意圖切換: ${currentIntentMode} → ${detectedIntent} (score: ${repairScore}/${shoppingScore})`);
      setIntentMode(detectedIntent, 'strong-intent-switch', 'system');
      return detectedIntent;
    }
    
    // 沒有強意圖，保持鎖定
    return currentIntentMode;
  }
  
  // auto 模式，首次檢測
  if (currentIntentMode === 'auto' && (repairScore > 0 || shoppingScore > 0)) {
    setIntentMode(detectedIntent, 'auto-detect', 'system');
  }
  
  return detectedIntent;
}
```

## 🎯 總結

目前實作的主要問題：

1. ❌ **鎖定過於嚴格**: 一旦鎖定維修模式，即使明確詢問商品也無法切換
2. ❌ **不對稱的鎖定邏輯**: 維修會鎖定，商品不鎖定
3. ❌ **歷史意圖檢測錯誤**: 使用受鎖定影響的檢測函式判斷意圖切換
4. ⚠️ **缺少強意圖切換**: 沒有機制在鎖定後檢測相反意圖

**核心建議**:
- 建立 `detectIntentPure()` 函式用於純粹的關鍵字檢測
- 在 `detectIntent()` 中增加「強意圖切換」邏輯（需要至少 2 個關鍵字）
- 統一 shopping 和 repair 的鎖定邏輯
- 增強 Console 日誌以便調試

這些修改應該能讓系統達到文件中描述的預期行為。
