## 🔍 根本原因分析

### 問題追蹤流程

#### 步驟 3 執行後的狀態

```javascript
chatHistory = [
  {role: 'user', content: '瓦斯洩漏'},          // 步驟 1
  {role: 'assistant', content: '維修回應1...', alignment: {...}},  // ← 有 alignment
  {role: 'user', content: '公司地址'},          // 步驟 2
  {role: 'assistant', content: '公司資訊...'},
  {role: 'user', content: '瓦斯洩漏'},          // 步驟 3
  {role: 'assistant', content: '維修回應2...', alignment: {...}}   // ← 有 alignment
]
```

#### 步驟 4 執行 `routeMessageByIntent`

```javascript
// 檢測意圖
lastIntent = detectIntentPure('瓦斯洩漏')  // 步驟 3 的內容
           = 'repair'

intent = detectIntent('插座發熱')  // 步驟 4
       = 'repair'

// 意圖沒有切換
intentChanged = ('repair' !== 'repair') = false

// ❌ 保留了所有歷史（包括有問題的 alignment）
payloadHistory = chatHistory.slice(-10)
```

#### 發送到後端的請求

```javascript
POST /api/repair/chat
{
  message: "插座發熱",
  history: [
    {role: 'user', content: '瓦斯洩漏'},
    {role: 'assistant', content: '...', alignment: {...}},  // ← 問題！
    {role: 'user', content: '公司地址'},
    {role: 'assistant', content: '...'},
    {role: 'user', content: '瓦斯洩漏'},
    {role: 'assistant', content: '...', alignment: {...}}   // ← 問題！
  ]
}
```

### 🚨 **問題根源：型別不匹配**

#### 後端定義

```python
class RepairChatReq(BaseModel):
    message: str
    history: List[Dict[str, str]] = []  # ← 只允許 Dict[str, str]
    session_id: Optional[str] = None
    topn: int = 5
```

**要求：** `history` 中的每個字典只能包含字串值。

#### 前端發送

```javascript
{
  role: 'assistant',
  content: '...',
  alignment: {...}  // ← Dict[str, Any]，不是 str！
}
```

**實際：** 包含了 `alignment` 物件（非字串）。

### ❌ **結果：後端驗證失敗**

- FastAPI Pydantic 驗證失敗
- 返回 **422 Unprocessable Entity** 或 **500 Internal Server Error**
- 前端觸發 `catch` 區塊，降級到商品搜尋
- 最終用戶看到錯誤結果

## 🔧 修復方案

### 方案：清理 history 中的非字串欄位

在發送到維修端點前，過濾掉 `alignment` 等額外欄位：

#### 修改位置：`frontend/index.html`

```javascript
if (intent === 'repair') {
  // 維修路由
  console.log('🔧 [Route] 路由到維修服務');
  
  // ✅ 清理歷史記錄，移除額外欄位（如 alignment）
  const cleanHistory = payloadHistory.map(msg => ({
    role: msg.role,
    content: msg.content
  }));
  
  const repairEndpoint = buildBackendUrl('repair/chat');
  const body = {
    message,
    history: cleanHistory,  // ✅ 使用清理後的歷史
    session_id: currentChatSession || sessionId,
    topn: 5
  };
```

### 修復原理

1. **過濾額外欄位**：只保留 `role` 和 `content`
2. **符合後端定義**：確保所有值都是字串
3. **不影響其他功能**：商品搜尋端點不受影響

## 🎯 根本問題總結

### 問題鏈

1. **前端 chatHistory 包含額外欄位**
   - `alignment` 用於商品對齊功能
   - 維修回應也被添加了這個欄位

2. **意圖持續時不清空歷史**
   - 連續維修查詢視為「意圖延續」
   - `payloadHistory` 保留了所有歷史

3. **後端型別驗證嚴格**
   - `List[Dict[str, str]]` 不允許非字串值
   - Pydantic 驗證失敗

4. **降級機制觸發**
   - 後端返回錯誤
   - 前端降級到商品搜尋
   - 用戶看到錯誤結果

### 修復策略

✅ **在發送前清理 history**
- 只保留 `role` 和 `content`
- 確保符合後端定義
- 不影響其他功能
