# 本地開發環境問題排查指南

## 🚨 常見問題：無法打開網頁

### 問題 1: 後端啟動失敗 - "Could not import module 'app'"

**原因：** uvicorn 在錯誤的目錄層級執行

**錯誤示範：**
```bash
# ❌ 錯誤：從根目錄直接執行
uvicorn app:app --reload

# ❌ 錯誤：雖然切換目錄，但 Python 路徑不正確
cd backend && uvicorn app:app --reload
```

**正確方法：**
```bash
# ✅ 使用提供的啟動腳本
./start_dev.sh

# ✅ 或手動從 backend 目錄啟動
cd backend
source .venv/bin/activate
uvicorn app:app --reload --reload-exclude '.venv/*' --host 0.0.0.0 --port 8000
```

---

### 問題 2: 服務不斷重載 (無限循環)

**原因：** uvicorn 監控到 `.venv` 資料夾變動

**症狀：**
```log
WARNING: WatchFiles detected changes in 'backend/.venv/...'
ERROR: Error loading ASGI app. Could not import module "app".
```

**解決方案：**
```bash
# 加上 --reload-exclude 參數排除虛擬環境目錄
uvicorn app:app --reload --reload-exclude '.venv/*'
```

---

### 問題 3: 端口被占用

**檢查端口使用狀況：**
```bash
# 檢查 8000 端口（後端）
lsof -i :8000

# 檢查 5173 端口（前端）
lsof -i :5173
```

**清理端口：**
```bash
# 殺掉占用端口的進程
kill -9 $(lsof -t -i:8000)
kill -9 $(lsof -t -i:5173)

# 或使用停止腳本
./stop_dev.sh
```

---

### 問題 4: 前端頁面空白或 404

**可能原因：**
1. 前端服務未啟動
2. 在錯誤的目錄啟動 HTTP server
3. 瀏覽器快取問題

**解決步驟：**
```bash
# 1. 確認前端服務運行中
lsof -i :5173

# 2. 確認從 frontend 目錄啟動
cd frontend
python3 -m http.server 5173

# 3. 清除瀏覽器快取
# Chrome: Cmd+Shift+R (Mac) 或 Ctrl+Shift+R (Windows)
```

---

### 問題 5: 修改程式碼後沒有反應

**後端（Python）：**
- ✅ 有 `--reload` 參數：自動重載
- ⚠️ 例外情況需手動重啟：
  - 修改 `.env` 檔案
  - 安裝新套件
  - 修改 `requirements.txt`

**前端（HTML/CSS/JS）：**
- 修改後直接重新整理瀏覽器（Cmd+R 或 F5）
- 如果沒反應，強制重新整理（Cmd+Shift+R）

## 🛠️ 快速修復流程

### 完整重啟（推薦）

```bash
# 1. 停止所有服務
./stop_dev.sh

# 2. 等待 2 秒
sleep 2

# 3. 重新啟動
./start_dev.sh
```

### 手動診斷步驟

```bash
# 步驟 1: 檢查虛擬環境
ls -la backend/.venv/bin/activate

# 步驟 2: 檢查 app.py 存在
ls -la backend/app.py

# 步驟 3: 測試虛擬環境可用
cd backend
source .venv/bin/activate
python -c "import fastapi; print('FastAPI OK')"

# 步驟 4: 測試 app 模組可導入
python -c "from app import app; print('App module OK')"

# 步驟 5: 啟動服務
uvicorn app:app --reload --reload-exclude '.venv/*'
```

## 🎯 使用啟動腳本的優點

### `./start_dev.sh` 功能：

1. ✅ **自動清理舊進程** - 避免端口衝突
2. ✅ **正確的目錄結構** - 從 backend 目錄啟動後端
3. ✅ **排除 .venv 監控** - 避免無限重載
4. ✅ **健康檢查** - 驗證服務是否成功啟動
5. ✅ **背景執行** - 同時運行前後端
6. ✅ **日誌分離** - backend.log 和 frontend.log
7. ✅ **狀態顯示** - 顯示 PID 和 URL

### `./stop_dev.sh` 功能：

1. ✅ **優雅停止** - 使用 pkill 停止所有相關進程
2. ✅ **清理完整** - 確保沒有殘留進程

## 💡 最佳實踐

### 開發流程

1. **每天開始開發時：**
   ```bash
   git pull  # 拉取最新代碼
   ./start_dev.sh  # 啟動服務
   ```

2. **修改代碼時：**
   - Python 檔案：自動重載（有 --reload）
   - 前端檔案：手動重新整理瀏覽器
   - .env 檔案：需要重啟後端

3. **結束開發時：**
   ```bash
   ./stop_dev.sh  # 停止服務
   git add . && git commit -m "..." && git push
   ```

### 避免常見錯誤

❌ **不要這樣做：**
```bash
# 從根目錄啟動後端
uvicorn app:app --reload

# 同時開多個相同的服務
# 先殺掉舊的再啟動新的

# 直接修改 CSV 後不清快取
# 需要呼叫 /api/admin/clear-cache
```

✅ **應該這樣做：**
```bash
# 使用提供的腳本
./stop_dev.sh && ./start_dev.sh

# 或完整的手動流程
cd backend
source .venv/bin/activate
uvicorn app:app --reload --reload-exclude '.venv/*' --host 0.0.0.0 --port 8000
```

## 🆘 仍然無法解決？

### 檢查清單

- [ ] 虛擬環境已建立：`backend/.venv/` 存在
- [ ] 依賴已安裝：`pip list` 顯示 fastapi, uvicorn
- [ ] app.py 存在：`backend/app.py` 存在
- [ ] CSV 資料存在：`data/VIEW_GOODS_enhanced.csv` 存在
- [ ] 端口未被占用：`lsof -i :8000` 和 `lsof -i :5173` 無輸出
- [ ] Python 版本正確：`python --version` >= 3.9
- [ ] 從正確目錄啟動：在 `SEARCH_Goods` 根目錄執行

### 完全重置

```bash
# 1. 停止所有服務
./stop_dev.sh
pkill -f uvicorn
pkill -f "http.server"

# 2. 清除虛擬環境
rm -rf backend/.venv

# 3. 重新建立虛擬環境
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

# 4. 返回根目錄重新啟動
cd ..
./start_dev.sh
```
