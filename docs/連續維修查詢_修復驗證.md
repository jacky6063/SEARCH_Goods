## 🔧 實施的修復

### 修復內容

#### 1. **修改 `routeMessageByIntent` 函數開頭**

```javascript
async function routeMessageByIntent(message, intent, options = {}) {
  // 🔄 檢測意圖切換（使用純粹檢測避免鎖定狀態污染）
  let lastIntent = null;
  if (chatHistory.length > 0 && !options._forceNewHistory) {  // ✅ 新增檢查
    // 查找最後一條使用者訊息
    for (let i = chatHistory.length - 1; i >= 0; i--) {
      if (chatHistory[i].role === 'user') {
        lastIntent = detectIntentPure(chatHistory[i].content);
        break;
      }
    }
  }
  
  const intentChanged = lastIntent && lastIntent !== intent;
  
  // 如果意圖切換或強制清空，清空歷史避免干擾
  const payloadHistory = (intentChanged || options._forceNewHistory) ? [] : chatHistory.slice(-10);  // ✅ 新增條件
```

#### 2. **更新日誌訊息**

```javascript
if (intentChanged) {
  console.log(`🔄 [Intent] 意圖切換: ${lastIntent} → ${intent}，清空對話歷史`);
} else if (options._forceNewHistory) {
  console.log(`🆕 [Intent] 強制清空歷史（降級或重試）`);  // ✅ 新增日誌
} else {
  console.log(`➡️ [Intent] 意圖延續: ${intent}，保留歷史 (${payloadHistory.length} 條)`);
}
```

#### 3. **修改維修服務降級邏輯**

```javascript
} catch (error) {

  // 降級到商品搜尋，強制清空歷史避免污染  // ✅ 更新註解
  return routeMessageByIntent(message, 'shopping', { ...options, _forceNewHistory: true });  // ✅ 添加選項
```

## 🎯 修復原理

### 問題根源回顧

1. 步驟 4「插座發熱」正確檢測為 `repair`
2. 正確路由到 `/api/repair/chat`
3. **後端返回錯誤**（可能是 HTTP 500）
4. 觸發 catch 區塊，降級到商品搜尋
5. ❌ **降級時重用了 `payloadHistory`**，導致後續路由混亂

### 修復邏輯

1. 添加 `_forceNewHistory` 選項標記
2. 降級時設置 `_forceNewHistory: true`
3. 強制清空對話歷史，避免污染
4. 確保降級後的路由是「乾淨」的狀態
