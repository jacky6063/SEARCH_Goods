# 意圖切換優化實作總結

## 📋 問題描述

**用戶反饋的場景：**
1. 首次輸入「我要購買女用包包價格在 3000~4000元之間」→ ✅ 正常顯示商品
2. 輸入「你們公司在哪裡」→ ✅ 正常顯示公司資訊
3. 輸入「電梯運行異音」→ ❌ **沒有執行維修模組，仍顯示包包資料**

**根本原因：**
前端判斷意圖為 `repair`，但將整個對話歷史（包含「女用包包」）傳給後端，導致後端被歷史訊息干擾，繼續使用商品模組。

---

## 🎯 解決方案

### 方案選擇：前端統一判斷 + 意圖切換檢測

**優點：**
- ✅ 最小改動，不需要修改後端邏輯
- ✅ 清晰分工：前端負責路由選擇，後端專注處理業務
- ✅ 性能更好：避免後端重複判斷意圖

### 2. 實作意圖切換檢測邏輯

**檔案：** `frontend/index.html` (line ~1647)

**核心邏輯：**
```javascript
async function routeMessageByIntent(message, intent, options = {}) {
  // 🔄 檢測意圖切換
  let lastIntent = null;
  if (chatHistory.length > 0) {
    // 查找最後一條使用者訊息
    for (let i = chatHistory.length - 1; i >= 0; i--) {
      if (chatHistory[i].role === 'user') {
        lastIntent = detectIntent(chatHistory[i].content);
        break;
      }
    }
  }
  
  const intentChanged = lastIntent && lastIntent !== intent;
  
  // 如果意圖切換，清空歷史避免干擾
  const payloadHistory = intentChanged ? [] : chatHistory.slice(-10);
  
  if (intentChanged) {
    console.log(`🔄 [Intent] 意圖切換: ${lastIntent} → ${intent}，清空對話歷史`);
  } else {
    console.log(`➡️ [Intent] 意圖延續: ${intent}，保留歷史 (${payloadHistory.length} 條)`);
  }
  
  // ... 後續路由邏輯
}
```

**運作機制：**
1. **查找上一次意圖**：從 `chatHistory` 中找到最後一條使用者訊息，重新判斷意圖
2. **比較意圖**：比較上次意圖與當前意圖
3. **條件清空歷史**：
   - 意圖切換 → `payloadHistory = []`（清空）
   - 意圖延續 → `payloadHistory = chatHistory.slice(-10)`（保留最近10條）
