> **問題日期：** 2025年11月13日  
> **測試場景：** 連續維修查詢時的意圖判斷錯誤

---

## 🐛 問題現象

### 測試結果記錄

| 測試順序 | 使用者輸入 | 預期結果 | 實際結果 | 狀態 |
|---------|-----------|---------|---------|------|

#### 現有邏輯（❌ 錯誤）

## 💡 改善建議方案

### 方案 A：移除「沒有切換時返回舊值」的邏輯（推薦）

**問題：** 當前邏輯假設「沒有切換 = 維持舊意圖」，但實際上應該「持續驗證當前意圖」。

**修改：** `detectIntent()` 函式

```javascript
function detectIntent(message) {
  const manualLocked = intentModeLock === 'manual' && currentIntentMode !== 'auto';
  if (manualLocked) {
    return currentIntentMode;
  }

  // 計算意圖分數
  let repairScore = 0;
  let shoppingScore = 0;
  
  REPAIR_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) {
      repairScore++;
    }
  });
  
  SHOPPING_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) {
      shoppingScore++;
    }
  });
  
  // 判定檢測到的意圖
  let detectedIntent = 'shopping';
  if (repairScore > shoppingScore && repairScore > 0) {
    detectedIntent = 'repair';
  } else if (shoppingScore > repairScore && shoppingScore > 0) {
    detectedIntent = 'shopping';
  }
  
  console.log('🎯 [Intent] 意圖分析:', {
    message: message.substring(0, 50),
    repairScore,
    shoppingScore,
    detected: detectedIntent,
    current: currentIntentMode,
    lock: intentModeLock
  });
  
  // ✅ 修改：系統鎖定時也要更新意圖（如果檢測到明確意圖）
  if (intentModeLock === 'system' && currentIntentMode !== 'auto') {
    // 如果檢測到明確的意圖（至少1個關鍵字）
    const hasExplicitIntent = 
      (detectedIntent === 'repair' && repairScore >= 1) ||
      (detectedIntent === 'shopping' && shoppingScore >= 1);
    
    if (hasExplicitIntent) {
      // 檢測到明確意圖時，無論是否切換都要更新
      if (detectedIntent !== currentIntentMode) {
        console.log(`🔄 [Intent] 意圖切換: ${currentIntentMode} → ${detectedIntent}`);
      } else {
        console.log(`✅ [Intent] 意圖持續: ${detectedIntent}`);
      }
      setIntentMode(detectedIntent, 'explicit-intent', 'system');
      return detectedIntent;
    }
    
    // 沒有明確關鍵字時才保持鎖定
    console.log(`🔒 [Intent] 保持鎖定: ${currentIntentMode} (無明確關鍵字)`);
    return currentIntentMode;
  }
  
  // auto 模式首次檢測
  if (currentIntentMode === 'auto' && (repairScore > 0 || shoppingScore > 0)) {
    setIntentMode(detectedIntent, 'auto-detect', 'system');
  }
  
  return detectedIntent;
}
```

**優點：**
- ✅ 解決連續相同意圖查詢時的更新問題
- ✅ 保留切換邏輯的完整性
- ✅ 日誌更清晰，區分「切換」和「持續」

**缺點：**
- 增加一次 `setIntentMode()` 調用（但影響很小）

### 方案 B：簡化邏輯，始終返回檢測結果

**修改：** 完全移除系統鎖定的特殊處理

```javascript
function detectIntent(message) {
  const manualLocked = intentModeLock === 'manual' && currentIntentMode !== 'auto';
  if (manualLocked) {
    return currentIntentMode;
  }

  // 計算意圖分數
  let repairScore = 0;
  let shoppingScore = 0;
  
  REPAIR_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) {
      repairScore++;
    }
  });
  
  SHOPPING_KEYWORDS.forEach(keyword => {
    if (message.includes(keyword)) {
      shoppingScore++;
    }
  });
  
  // 判定意圖（純粹基於關鍵字）
  let detectedIntent = 'shopping';
  if (repairScore > shoppingScore && repairScore > 0) {
    detectedIntent = 'repair';
  } else if (shoppingScore > repairScore && shoppingScore > 0) {
    detectedIntent = 'shopping';
  }
  
  console.log('🎯 [Intent] 意圖檢測:', {
    message: message.substring(0, 50),
    repairScore,
    shoppingScore,
    detected: detectedIntent
  });
  
  // ✅ 簡化：始終返回檢測結果，由調用方決定是否切換
  return detectedIntent;
}
```

**優點：**
- ✅ 邏輯極簡，容易理解和維護
- ✅ 沒有狀態依賴，避免時序問題
- ✅ 行為可預測

**缺點：**
- ❌ 失去了系統鎖定的保護機制
- ❌ 可能導致意圖切換過於頻繁

## 🎯 總結

### 問題根源

**「插座發熱」查詢失敗**的真正原因很可能是：

1. **系統鎖定邏輯過於保守**

   - 只處理了「意圖切換」的情況
   - 沒有處理「連續相同意圖」的情況

- 保留系統鎖定的保護機制
